# CSS 개발 규칙 — 국민의 부름

## 2026-10-21 전역 토큰 단일 생성 계약

- **유일한 DOM 생성 함수**: `GukminStatus.createToken({type,id?,name?,label?,icon?,amount?,state?,entry?,classes?})`. 모든 의미 있는 토큰은 `span.token.token-icon-pill` 루트, SVG `.token-icon`, `.token-name`을 같은 순서로 반환한다. 변화 토큰이면 `.impact-arrow` SVG + `.impact-amount`를 뒤에 붙인다.
- `type`: `metric` 상태 스탯(해당 `metric-*` 팔레트), `trait`/ `interest` 특성 정의 고유색, `school` 재학·졸업, `attribute` 출생지·집안·역할, `context` 학교 유형·조건·설명. 기존 `pill/traitToken/metricImpact`는 호환용 위임 함수이며 독립 DOM을 만들 수 없다.
- 단일 디자인: **단색 의미 배경 + 흰 SVG + 흰 이름 + 알약형의 동일한 높이/여백/테두리**. 숫자는 이모지나 텍스트 `+2`가 아닌 흰 SVG 삼각형 + 절댓값. 부정적 변화도 스탯 고유색을 유지하며 아래방향 SVG로 표현한다.
- 인게임 프로필·학교/학력·특성·일상 모눈 종이 선택/최종 정리·인생기록·시험지/고교 지원서 영향 미리보기·시스템 검증 UI·출생 인트로가 위 생성기를 공유한다. 화면별 CSS는 그룹 간격과 이벤트 연출만 담당하고 개별 토큰을 투명하게 만들거나 색/아이콘 규칙을 뒤집지 않는다.
- 공통 스타일 `:root .token.token-icon-pill`에서 색상 변수·높이·여백·글자·아이콘 규격을 관리한다. 세부 색상은 의미에 맞게 `--gauge-color`, `--trait-color`, `--token-fill`로 주입한다. 이 파일 외 파일에 토큰 모양을 복제하거나 원시 `.life-delta` 구조를 만들지 않는다.


## 2026-10-20 일상 선택 종이 UI 계층과 토큰

- `#dailyModalHeading`은 사건 제목 메타/보조 타이포(.89rem), 나이·단계는 .63rem으로 낮추고 메인 사건 설명 `.daily-choice-story`를 약 1.1rem, weight 650으로 승격한다. 기존 `GukminMarkup.render`의 strong, em, mark, del은 DOM을 그대로 유지하며 종이 스킨에서 시각적 강조만 설정한다.
- 중복 `어떻게 할까?` 소제목은 제거하고 `inline-choices` 그룹의 aria-label로 의미를 보존. 헤더의 `접기⌄` 버튼도 제거, 드래그 가능한 그립·헤더 및 Escape/바깥쪽 탭으로 접는다.
- `GukminStatus.metricImpact(id,delta)`가 스탯 정의의 동일 SVG/이름을 쓰고 정방향/역방향 삼각형 SVG를 생성한다. `.metric-*`에 정의된 `--gauge-color`를 배경으로 쓰며 아이콘/글씨/삼각형 모두 흰색. 일상 선택·선택 직후 종이 결과·영구 인생 기록에서 함께 쓴다.
- 특성도 기존 `traitToken` / `--trait-color`를 그대로 쓰고 종이 스킨에서 고유 단색 배경 + 흰색 아이콘/텍스트를 적용한다. 숫자 증감이 없으면 정직한 안내를 보여준다.
- 일상 선택 확정 뒤 같은 종이에서 행동·결과 서술·실제 변화만 정산해 표시하고 하단 버튼은 `인생 기록으로 돌아가기`로 변경. 기존 저장·검토 대기 흐름은 유지한다.
- 닫힘은 `GukminSheet` 공통 스프링 높이 보간을 유지하고, `.paper-choice-sheet[open].is-dismissing::backdrop` 전환으로 배경도 부드럽게 사라진다. 별도 CSS 닫기 transform·JS 타이머 추가 없음.
- 길이 단위는 rem/em 및 dvh. 작은 화면에서는 선택지/결과 본문만 스크롤하고 헤더·그립·하단 버튼은 보존한다.



## 2026-10-20 일기 시트 제스처 정합성 보강

- `GukminSheet`의 `dismissible:true`는 최저 스냅 아래로도 실제 드래그 높이를 0까지 추적한다. 비삭제형은 기존 최저 스냅을 유지한다.
- 종이의 닫기 동작도 동일 스프링 컨트롤러에서 높이를 0으로 보간하고 종료 후 `onDismiss`를 호출한다. CSS 전용 하향 변환과 타이머를 제거했다.
- 시트 외관은 클래스별로 분리하되 드래그·스냅·닫기 물리는 공통 코드만 사용한다. 터치 영역은 그립/헤더이며 본문은 스크롤한다.

## 2026-10-20 모눈 종이 선택 시트·공통 스냅 시스템

- `js/sheetController.js` 의 `GukminSheet.create`가 기존 기록 시트와 일상 선택지 모두의 Pointer Events·관성·스프링 및 키보드 그립 조작을 담당한다. DOM 재생성 없이 `--snap-height` / `--sheet-drag-height` / `--sheet-motion-height` 변수로 높이를 제어한다.
- 메인 `#lifeSheet`는 `steps` 20/55/90%, `dismissible:false` (항상 존속). 일상 `#dailyChoiceDialog`는 `steps` 62/94%, `dismissible:true` (아래로 내려 접기). 단계 수·비율·최솟값·최대값은 JS 구성, 페인트/모양은 CSS 클래스 소유.
- `.paper-choice-sheet`는 독립적인 흰 모눈 배경 + `Noto Serif KR / Batang` 서체 + 왼쪽 바인더 구멍 + 조용한 체크형 선택 목록. 기존 시험지·지원서·메인 기록 시트에는 이 스타일이 전파되지 않는다.
- 일상 선택은 선택 행을 표시한 다음 `#dailyPaperConfirm`으로 확정. 실제 정산 뒤 같은 종이에 결과와 정확한 변화가 나타나고 확인 후 기존 기록으로 돌아간다. 대기 중인 선택·정산 대기는 기존 단일 세이브 상태를 유지한다.
- 본문은 별도 `.daily-modal-body` 단일 스크롤, 그립·헤더만 드래그. 320×568에서도 버튼·본문에 접근 가능해야 하며 `prefers-reduced-motion`을 보존한다.


## 2026-10-20 경험 활용과 결과 전망

- `.daily-choice-advantage`는 기존 선택 행 안에서 활용 가능한 특성·활동 경험을 옅은 초록 알약으로 표시한다. 필요 조건은 잠긴 행의 읽을 수 있는 문구로 표시한다.
- `.daily-choice-outlook`은 큰 도전의 알려진 비용 아래에서 준비 조건·성과 가능성을 설명한다. 확정 효과 배지와 구분되는 낮은 대비의 본문이며, 긴 문구는 기존 모달 본문 안에서 줄바꿈·스크롤한다.
- 추가 크기·간격은 rem/em이다. PC·모바일 공통 선택 행에 적용하며, 기존 2열·영구 시트·네이티브 모달의 높이/접기/단일 스크롤 구조는 변경하지 않는다.

> **필수 선행 문서.** 앞으로 `css/style.css` 또는 레이아웃·폰트 스케일에 영향을 주는 코드를 수정하기 **전에 이 문서를 먼저 읽고**, CSS 관련 변경사항이 있으면 **같은 작업·커밋에서 이 문서도 갱신**한다. `AGENTS.md`에도 이 규칙을 연결한다.

## 최신 화면 계약 — 2026-10-20 사용성 보강

이 절은 아래 날짜별 이력과 충돌할 때 우선한다. 현행 게임은 0~19세 학생 생애 콘텐츠를 재생한다.

- 모바일의 포스터·상태 2열과 영구 인생기록 시트 20/55/90dvh 구조는 유지한다. 상태 카드만 내용 높이로 확장하여 스탯을 작은 중첩 스크롤 안에 가두지 않는다. 본문 하단 여백은 초기 시트 높이인 20dvh에 맞춘다. PC 레이아웃은 유지한다.
- 일상 선택은 중앙 카드 한 장, 내부 선택은 낮은 대비의 개별 행으로 구분한다. 나이·생애 배경 → 상황 → 행동 → 실제 효과·부담 순서로 읽으며 본문만 스크롤한다. 접기는 최소 2.75rem 터치 영역이다. 헤더의 프로그램상 포커스에는 외곽선을 붙이지 않고 버튼의 키보드 포커스는 유지한다.
- 시험·진학 창에 `.life-modal-collapse`를 제공하고 축소 시 시트 헤더의 `#resumeMajorChoice`를 표시한다. 제목·행동·확정 영역을 보존하며 선택지 목록만 스크롤한다. 모바일 시험 안내의 중복 문장을 줄였다.
- 학교의 필수 지원 기준은 항상 표시한다. 부가 학습·거리·생활 정보 `.life-school-extra`는 선택한 학교에서 펼친다. 잠긴 학교는 전체 투명도를 낮추지 않고 `.life-answer.life-answer-locked`와 읽을 수 있는 미달 문구로 구분한다.
- 모바일 포스터의 생애 표시는 작은 글씨로 분리하고 상태 문구는 의도한 줄바꿈을 유지해 이름·단계와 충돌하지 않게 한다.
- 특성 토큰은 `.trait-control` 버튼으로 감싸며 누르면 `#traitInfo`에서 설명을 읽는다. 특성 색과 학교·수저 토큰 규격은 보존한다. 결과 토큰도 특성 고유색을 사용하고 관심 발견을 정식 특성과 구분한다.
- 동일 등급 안의 성적 변화도 성적표의 원점수 전후·실제 변화량으로 보여 준다. 원래 기록을 바꾸지 않는다. 애니메이션 없는 일반 턴에서는 기존 로그 DOM을 재사용한다.
- 전환 연출과 네이티브 선택 모달은 동시에 표시하지 않는다. 전환이 끝나면 저장된 대기 선택을 이어서 표시한다.
- 학생 생애의 마지막에는 `.life-chapter-complete`에서 현재 공개 콘텐츠의 범위와 새 인물 시작 버튼을 표시한다. 새 인물 생성은 기존 확인 절차를 사용한다.
- 모든 크기는 rem/em 및 viewport 비율을 사용한다. `prefers-reduced-motion`을 보존한다. 자동 검증 해상도는 320×568, 360×640, 390×844, 1365×900이며 실기기 브라우저 검증을 대신하지 않는다.

## 1. 기준 글꼴 크기와 단위

- **모바일/기본**: `:root { font-size: 16px; }` (기존 모바일 시각 크기 유지).
- **PC 761px 이상**: `@media (min-width: 47.5625em) { :root { font-size: 15px; } }` (PC UI를 소폭 축소).
- **루트가 아닌 선택자의 길이·크기·간격·테두리·그림자 오프셋은 `rem` 또는 `em`으로 작성**한다. 기본 `1rem`은 현재 문서 루트 글꼴 크기를 따른다.
- 일반적인 크기·간격은 `rem`, 글꼴/컴포넌트 내부 비례 크기는 `em`을 기본으로 한다. 포스터 내부의 글꼴 크기도 `em`을 사용한다.
- 상위 컴포넌트 비율·유연한 레이아웃을 위해 `%`, `fr`, `auto`, `vw`, `dvh`, `calc()`, `clamp()` 등은 필요한 경우 유지할 수 있다. 고정 `px`은 **루트 글꼴 크기 정의에만** 허용한다.
- 반응형 분기 `@media`는 **`em` 단위**로 작성한다. 미디어 쿼리의 `em`은 문서에서 변경한 `:root` 값이 아니라 브라우저 초기 폰트 크기(통상 16px)를 기준으로 평가되므로, 루트 크기를 바꿔도 기기 분기는 안정적이다.
- 예: `padding: 1rem`, `gap: .75rem`, `border: .0625rem solid`; 잘못된 예: `padding: 16px`, `width: 280px`.

## 2. 현재 반응형 레이아웃 계약

**PC (`min-width:47.5625em`, 약 761px~)**

- `.game`: 2열 화면 구성.
- 왼쪽 `.desktop-left > .status`: **세로 flex**. `#playerPosterMount`(상단 포스터)와 `.profile`(하단 학력/특성)이 `width:100%; align-self:stretch; flex-basis:0`로 **항상 같은 가로 너비**.
- 포스터는 부모의 실제 flex 크기에 맞춰 `width:100%; height:100%; aspect-ratio:auto`. 이미지/텍스트 영역은 `js/poster.js`가 반환하는 DOM 내부에 독립 레이어로 위치. 텍스트·이미지를 강제로 늘리지 않는다.
- 오른쪽 `.desktop-right`: 상단 능력치 박스 + 아래 기록/선택 패널. PC에서는 기록 패널이 바텀시트가 아님.
- PC 전체는 화면 높이 안에 배치, 필요한 경우 이력·프로필 영역 **내부만** 스크롤.

**모바일 (`max-width:47.5em`, 약 760px 이하)**

- 포스터+학력 상태표 **가로 2열**, 아래에 능력치, 화면 아래에 고정·항상 열린 히스토리 바텀시트.
- 기존 모바일 배치/치수를 유지하는 것이 우선이다. PC 조정은 PC 미디어 쿼리에 격리한다.
- 440px 이하에서는 기존 능력치 2열 레이아웃을 유지한다.

## 12. 바텀시트 조작과 상태 스탯 계층 (긴급 회귀 수정)

- 모바일은 처음부터 `is-minimized`(하단에 헤더와 진행도를 남기는 20dvh, 8.5~12rem)로 시작한다. 손잡이 클릭은 축소/90dvh 확장 토글, 손잡이 또는 헤더(버튼 제외)의 상하 Pointer Events 드래그는 실제 높이를 따라오다가 이동 방향에 따라 축소/확장으로 스냅한다. PC `.sheet` 크기는 그대로다.
- 축소 중에는 `.sheet-content`만 숨겨 실수로 선택지를 누르지 않도록 한다. 선택·기록의 기존 단일 스크롤 구조와 저장/선택 상태는 변경하지 않는다.
- `.gauges-list`는 정신병(`stress`)과 건강(`health`)만 2열에 나란히 보여 준다. 재산·학업 등 나머지는 2열 전체 너비의 개별 행이다. 저장 ID `stress`는 구 세이브 호환을 위해 유지한다.

## 13. 모바일 터치 드래그 보강

- 손잡이·헤더에 `touchstart/move/end` 경로를 추가해 모바일에서 포인터 이벤트가 취소되어도 실제 시트 높이를 추적한다. 기록 영역 스크롤은 건드리지 않는다. 드래그 뒤 합성 클릭은 억제한다.

## 14. 바텀시트 3단계 스냅 (2026-10-20)

- 모바일 시트는 축소 약 20dvh(is-minimized), 중간 55dvh(is-middle), 전체 약 90dvh(is-expanded) 세 단계. 축소에서만 본문 숨김. 중간·전체는 기존 단일 sheet-content 스크롤 사용.
- 손잡이 탭은 축소→중간→전체→축소 순환. 손잡이/헤더 스와이프는 실제 높이를 따라가다 가까운 단계에 정착하며, 의도적 48px 이상 이동은 최소 한 단계 변경. 터치 이벤트 드래그와 드래그 후 클릭 억제 유지. PC·저장 영향 없음.
- 12~13절의 두 단계 기술은 이 세 단계 설명이 대체한다.

## 15. 일상 선택의 정보 위계 (2026-10-20)

## 15. 모바일 인생기록 시트 입력 처리 (2026-10-20)

- `html/game.html`의 기존 `#lifeSheet > #sheetToggle`, `.sheet-head`, `.sheet-content`를 유지한다. 바텀시트는 게임의 상시 UI이며 팝업/오버레이 생성·제거, 검은 배경 덮기, 본문 교체를 하지 않는다.
- 높이·경계·이징·축소 시 본문 숨김은 `css/style.css` 전담. 기본/축소는 `--sheet-small-height`(20dvh 내외), 중간은 55dvh, 전체는 `--sheet-large-height`(90dvh 내외). 선택 대기 여부가 시트 높이를 덮어쓰지 않는다.
- `js/game.js`는 단일 Pointer Events 경로로 손잡이와 헤더만 드래그한다. 버튼·링크에서 시작한 포인터는 무시한다. 이동 중에만 임시 CSS 변수 `--sheet-drag-height`를 전달하고 종료 시 삭제한다. style.height 직접 수정이나 Touch/Pointer 이벤트 중복 등록 금지.
- 손잡이 클릭·키보드는 축소→중간→전체→축소 순환. 드래그는 위치를 따라가되 방향과 임계거리로 인접 단계에만 정착한다. 드래그 후 합성 클릭을 억제하고, 기록/선택 단일 스크롤 및 PC 레이아웃은 보존한다.
- 높이 전환은 CSS, `prefers-reduced-motion` 존중. `tests/browser.mjs`에서 실제 터치·마우스 드래그·키보드 입력을 회귀 검증한다.

## 16. 일상 선택 시각 피로 축소 (2026-10-20)

- 상황: 카드 배경과 굵은 색 외곽선 대신 제목/설명 중심의 타이포그래피와 얇은 하단 경계선. 선택: 배경 없는 개별 행, 아주 약한 경계선. 중복 시각 강조 제거.

## 17. 특성 상단 배치와 적성 토큰 (2026-10-20)

- 인게임 상태 카드의 DOM은 특성 flex-wrap → 구분선 → 상태 스탯 순서. 적성(문과/이과/예체능/체육) 4색 토큰은 공용 학사모 SVG를 공유한다. 흥미 탐색용 숨은 태그/특성은 상태 UI에 표시하지 않는다.

## 22. 관성·스프링 바텀시트 전환 (2026-10-20)

- 원본 물리 애니메이션을 Pointer Events 한 경로로 통합하며 마우스/터치 중복 입력 제거. 드래그 중 프레임 제한, 스프링 중 재드래그 취소, 리마운트 해제, reduced-motion 즉시 정착, 직전 합성 클릭 180ms 억제를 적용한다.

## 23. 축소 상태에서도 본문 렌더 유지 (2026-10-20)
