# CSS 개발 규칙 — 국민의 부름

> **필수 선행 문서.** 앞으로 `css/style.css` 또는 레이아웃·폰트 스케일에 영향을 주는 코드를 수정하기 **전에 이 문서를 먼저 읽고**, CSS 관련 변경사항이 있으면 **같은 작업·커밋에서 이 문서도 갱신**한다. `AGENTS.md`에도 이 규칙을 연결한다.

## 1. 기준 글꼴 크기와 단위

- **모바일/기본**: `:root { font-size: 16px; }` (기존 모바일 시각 크기 유지).
- **PC 761px 이상**: `@media (min-width: 47.5625em) { :root { font-size: 15px; } }` (PC UI를 소폭 축소).
- **루트가 아닌 선택자의 길이·크기·간격·테두리·그림자 오프셋은 `rem` 또는 `em`으로 작성**한다. 기본 `1rem`은 현재 문서 루트 글꼴 크기를 따른다.
- 일반적인 크기·간격은 `rem`, 글꼴/컴포넌트 내부 비례 크기는 `em`을 기본으로 한다. 포스터 내부의 글꼴 크기도 `em`을 사용한다.
- 상위 컴포넌트 비율·유연한 레이아웃을 위해 `%`, `fr`, `auto`, `vw`, `dvh`, `calc()`, `clamp()` 등은 필요한 경우 유지할 수 있다. 고정 `px`은 **루트 글꼴 크기 정의에만** 허용한다.
- 반응형 분기 `@media`는 **`em` 단위**로 작성한다. 미디어 쿼리의 `em`은 문서에서 변경한 `:root` 값이 아니라 브라우저 초기 폰트 크기(통상 16px)를 기준으로 평가되므로, 루트 크기를 바꿔도 기기 분기는 안정적이다.
- 예: `padding: 1rem`, `gap: .75rem`, `border: .0625rem solid`; 잘못된 예: `padding: 16px`, `width: 280px`.

## 2. 현재 반응형 레이아웃 계약

**PC (`min-width:47.5625em`, 약 761px~)**

- `.game`: 2열 화면 구성.
- 왼쪽 `.desktop-left > .status`: **세로 flex**. `#playerPosterMount`(상단 포스터)와 `.profile`(하단 학력/특성)이 `width:100%; align-self:stretch; flex-basis:0`로 **항상 같은 가로 너비**.
- 포스터는 부모의 실제 flex 크기에 맞춰 `width:100%; height:100%; aspect-ratio:auto`. 이미지/텍스트 영역은 `js/poster.js`가 반환하는 DOM 내부에 독립 레이어로 위치. 텍스트·이미지를 강제로 늘리지 않는다.
- 오른쪽 `.desktop-right`: 상단 능력치 박스 + 아래 기록/선택 패널. PC에서는 기록 패널이 바텀시트가 아님.
- PC 전체는 화면 높이 안에 배치, 필요한 경우 이력·프로필 영역 **내부만** 스크롤.

**모바일 (`max-width:47.5em`, 약 760px 이하)**

- 포스터+학력 상태표 **가로 2열**, 아래에 능력치, 화면 아래에 고정·항상 열린 히스토리 바텀시트.
- 기존 모바일 배치/치수를 유지하는 것이 우선이다. PC 조정은 PC 미디어 쿼리에 격리한다.
- 440px 이하에서는 기존 능력치 2열 레이아웃을 유지한다.

## 3. CSS 수정 시 필수 순서

1. 이 문서 `docs/developing/CSS.md`를 **먼저 읽기**.
2. `docs/developing/UI.md`, `docs/developing/RUNTIME.md`와 실제 `css/style.css`, `index.html`에서 관련 DOM·레이아웃 확인.
3. 동일 선택자에 덧붙이는 임시 패치보다, **원래 규칙을 수정**하고 불필요한 충돌 규칙을 정리.
4. 루트 이외 `px` 도입 금지, 모바일 회귀·PC 패널 너비·텍스트 넘침·포스터 이미지 비율 확인.
5. `node tests/smoke.mjs` 실행 및 가능하다면 대표 크기의 실제 브라우저 렌더 확인.
6. **CSS 관련 설계나 규칙이 달라지면 이 파일도 같은 커밋에서 수정**. 갱신할 변경점이 없더라도 기존 계약과 맞는지 확인한다.

## 4. 검증 기준 (2026-10-19)

- PC 기준 루트 글꼴: **15px**, 모바일: **16px**.
- PC 포스터와 하단 상태표의 `getBoundingClientRect().width` 값이 같아야 함.
- 모바일 바텀시트는 `position:fixed`, 아래쪽에 위치해야 하며 PC에는 적용되지 않아야 함.
- 현재 스토리라인/진행 로직은 비활성화된 UI 기반 시연. CSS 작업 중 게임 진행을 임의로 도입하지 않는다.

## 5. 화면 3종과 학교·특성 토큰 (2026-10-19)

- 루트 `index.html`은 대기로 리다이렉트. `html/waiting.html`, `html/game.html`, `html/result.html`은 각각 정적 `<base href="../">`를 적용한 `css/style.css`로 공통 CSS를 불러오는 독립 문서. GitHub Pages에서는 `/callOfgukmin/css/style.css`, 로컬 개발에서는 상위 경로 기준. 모두 공통 `css/style.css`를 사용하나, 대기/결과는 `.waiting-screen`·`.result-screen` 접두 선택자로 독립 레이아웃을 소유한다.
- 인게임 반응형 골격(`.game`, `.desktop-left`, `.desktop-right`, `.status`, `.sheet`)은 유지한다. PC 왼쪽 포스터/프로필 동일 너비, 모바일 고정 바텀시트는 여전히 필수 계약이다.
- 속성 스탯은 `.attribute-list`·`.attribute-row`, 학교는 기존 `.school-list`·`.school-row`와 `.school-token`을 사용한다. **새 카드 컴포넌트 없음**. `.school-token-active`만 재학 강조, `.school-token-complete`는 졸업 톤.
- 상태 스탯은 `.gauges-list`에 동적 항목을 넣는다. 기존 `.gauges`는 전체 박스 및 상단 라벨/하단 특성의 컨테이너. `.trait-section`은 프로그래스 아래에 위치한다.
- 학교/특성/속성 토큰은 `.token-icon-pill`과 `.token-icon`을 공유하며, **알약 배경 + 내부 흰색 둥근 선 SVG 아이콘 + 이름**을 보존한다. 구체 색상과 활성 상태는 종류별 클래스로 구분.
- PC 상태 내부는 2열, 모바일 760px 이하 4열·440px 이하 2열 기준을 상태 `.gauges-list`에 적용한다. `:root` 이외의 크기/간격은 `rem`/`em` 기준이다.
- 새 화면은 뷰별 컨테이너에서만 레이아웃을 제어하며, 기존 게임 진행 코드를 CSS 작업과 함께 되살리지 않는다. 후속 폰트 크기·토큰 디자인 변경에도 **이 파일을 함께 검토·갱신**한다.

## 6. 공통 선택·진행도 (2026-10-19)

- `.choice-timing`은 `.sheet-head` 바로 아래, 스크롤 기록 바깥의 고정 높이 영역이다. 데이터의 다음 선택 예정 턴·대기를 표현한다.
- 기존 기본 상태/미리보기 액션은 제거했다. `.action-area`는 현재 선택이 있을 때만 표시하고 `.inline-choices`에 N개의 일상 선택 버튼을 넣는다. 한방 전용 팝업의 시각 디자인은 이번 범위에 포함하지 않는다.
- PC 2열, 포스터/프로필 동일 너비, 모바일 상시 열린 53dvh 바텀시트·학교/특성 알약은 보존한다. 모바일 액션은 시트 높이의 최대 60%에서 내부 스크롤하여 기록 공간을 남긴다. 상태 패널은 기존 페이지 스크롤로 접근한다.
- 개발 검증 도구 `.system-tools`는 `?systems=1`에서만 표시한다. 기본 플레이 UI에 개발용 버튼이나 미리보기 안내를 노출하지 않는다.
- 길이 단위는 rem/em 중심이다. Chromium 1365×900, 390×844, 360×640에서 실제 선택·졸업 토큰·동적 스탯·대기·가로 넘침과 시트 위치를 검증했다. 기록 중요도 minor는 작은 기록으로 표시한다.

## 7. 출생 인트로의 스타일 격리 (2026-10-19)

- 신규 `.birth-intro*` 선택자는 `html/waiting.html`의 출생 오버레이에만 적용한다. `.game`, `.status`, 모바일 기록 바텀시트의 구조·크기는 이 연출과 별개로 유지한다.
- 카드 폭은 `min(100%, rem)`, 간격과 외곽선은 `rem/em`, 기기 분기는 `em` 사용. 화면 높이가 낮을 때 카드/문구를 줄여 오버플로를 피하고 모바일 하단의 건너뛰기는 안전 영역을 고려한다.
- 애니메이션은 `birth-appear`, `birth-seal`, `birth-reveal`, `birth-grid`에 한정. `prefers-reduced-motion`에서는 애니메이션을 제거하고 JS가 인트로 자체를 건너뛴다.
- 상단 포스터와 하단 상태표의 기존 PC 동일 너비, 모바일 가로 배열, 게임 바텀시트는 변경하지 않는다. 스타일 격리 및 단위 준수를 정적 검증하되 실제 화면 가로 넘침은 브라우저에서 별도 확인한다.

## 8. 출생 재력 토큰 (2026-10-19)

- 출생 인트로도 `GukminStatus.traitToken()`으로 인게임과 같은 `.token-icon-pill` SVG 알약을 렌더한다. 별도 카드/도형 컴포넌트는 만들지 않는다.
- `.trait-tier-{soil,bronze,silver,gold,diamond}`는 갈색→청록빛 다이아 색상을 각각 소유한다. 기본 특성 토큰의 디자인, 모바일 배치, 인트로 구조를 변경하지 않는다.
- 토큰 간격은 `rem` 기준. 레이아웃 스케일 및 기존 모바일 바텀시트 규칙 유지.

## 9. 시험지·학교 지원서 종이 모달 (2026-10-19)

- `.life-choice-dialog`·`.life-modal-*`·`.life-answer*`는 게임의 독립적인 네이티브 dialog 스타일. 본문은 밝은 종이 톤이며 숫자 선택지, 선발 조건, 수치 증감 배지를 렌더한다.
- 모바일 `max-width:47.5em`에서 다이얼로그가 뷰포트 내에 들어오고 선택지 영역만 스크롤되도록 한다. 게임 PC 2열·모바일 상시 열린 바텀시트·출생 인트로는 변경하지 않는다.
- 로고 이미지가 있는 학교만 `.life-school-crest img`를 렌더하고, 나머지는 학교명을 줄인 **임시 문자 마크**를 사용한다.
- 새 규칙의 길이/선택자 단위는 `rem/em`; 루트 `px` 외 신규 `px` 없음.


## 10. 세로 일상 선택 · 지표 색상 · 종이 시험지 (2026-10-19)

- .inline-choices는 세로 flex-column 전체 너비이며 .daily-choice-*은 선택명·선택 후 상황·증감 배지를 계층적으로 그린다. 기존 PC 2열과 모바일 하단 고정 기록 시트는 변경하지 않는다.
- .gauge-title 내부 SVG 아이콘을 공통 렌더링하고 --gauge-color 변수로 각 스탯의 색을 정한다. 내신은 #85bcff 파랑, 모의고사는 #f5b65e 주황으로 분리한다. 각 예상 등급은 게이지 옆 문구로 표현한다.
- .life-exam-paper는 실제 시험지 상단의 교시·영역·성명/학년/수험번호 서식, 문제 번호, ①~⑤ 선택지를 창작 시험지로 재구성한다. 원본 시험 문제나 기관 로고를 복제하지 않는다.
- 새 규칙은 모두 rem/em 단위를 사용하고 viewport 폭에 따라 글꼴과 종이 안쪽 여백만 조절한다.


## 11. 출생 신고서·시트 단일 스크롤·스탯 레이아웃 (2026-10-19)

- 모바일은 **포스터 + 상태 스탯**을 상단 2열로, **속성 스탯**을 그 아래 카드로 옮겼다. PC는 포스터·상태 스탯을 왼쪽, 속성 스탯·인생기록을 오른쪽에 놓는다. 포스터와 같은 열의 상태 스탯 너비가 일치한다.
- 바텀시트는 닫히지 않는다. 선택/최신 기록은 `.sheet-content` 단일 스크롤 아래에 위→아래 순서로 배치하고 `.action-area` 및 `.log` 개별 스크롤은 사용하지 않는다. 상단 손잡이·헤더에만 드래그를 연결하고 기록 영역은 `touch-action:pan-y`로 일반 스크롤한다. 초기/스냅 높이는 아래 최신 12절을 따른다.
- `.daily-choice-effect.metric-*`는 기존 상태 스탯의 `--gauge-color` 변수를 직접 공유하고 SVG 아이콘을 `GukminStatus.pill`로 통일한다. `.life-answer-seal`은 시험지/학교 지원서 선택에 붉은 인주 도장 느낌을 표시한다.
- 출생 화면은 기존 오버레이의 테마와 카드 규격을 유지하면서 이름·출생지·가정·재력 토큰·10초 프로그레스·출생 버튼만 보여 준다. `.birth-intro-field`는 `dl`/dt/dd 시맨틱 구조. 새 규칙은 rem/em 사용, 크기 대응은 em 미디어 쿼리.
- 기존 문서 2~6절의 상태·속성 상하 위치, 고정 53dvh, 선택 60% 내부 스크롤, 인트로 3초 부분은 **이번 최신 계약으로 대체**된다. CSS 레이아웃 변경 시 이전 배치 기대 테스트도 함께 갱신한다.

## 12. 바텀시트 조작과 상태 스탯 계층 (긴급 회귀 수정)

- 모바일은 처음부터 `is-minimized`(하단에 헤더와 진행도를 남기는 20dvh, 8.5~12rem)로 시작한다. 손잡이 클릭은 축소/90dvh 확장 토글, 손잡이 또는 헤더(버튼 제외)의 상하 Pointer Events 드래그는 실제 높이를 따라오다가 이동 방향에 따라 축소/확장으로 스냅한다. PC `.sheet` 크기는 그대로다.
- 축소 중에는 `.sheet-content`만 숨겨 실수로 선택지를 누르지 않도록 한다. 선택·기록의 기존 단일 스크롤 구조와 저장/선택 상태는 변경하지 않는다.
- `.gauges-list`는 정신병(`stress`)과 건강(`health`)만 2열에 나란히 보여 준다. 재산·학업 등 나머지는 2열 전체 너비의 개별 행이다. 저장 ID `stress`는 구 세이브 호환을 위해 유지한다.

## 13. 모바일 터치 드래그 보강

- 손잡이·헤더에 `touchstart/move/end` 경로를 추가해 모바일에서 포인터 이벤트가 취소되어도 실제 시트 높이를 추적한다. 기록 영역 스크롤은 건드리지 않는다. 드래그 뒤 합성 클릭은 억제한다.

## 14. 바텀시트 3단계 스냅 (2026-10-20)

- 모바일 시트는 축소 약 20dvh(is-minimized), 중간 55dvh(is-middle), 전체 약 90dvh(is-expanded) 세 단계. 축소에서만 본문 숨김. 중간·전체는 기존 단일 sheet-content 스크롤 사용.
- 손잡이 탭은 축소→중간→전체→축소 순환. 손잡이/헤더 스와이프는 실제 높이를 따라가다 가까운 단계에 정착하며, 의도적 48px 이상 이동은 최소 한 단계 변경. 터치 이벤트 드래그와 드래그 후 클릭 억제 유지. PC·저장 영향 없음.
- 12~13절의 두 단계 기술은 이 세 단계 설명이 대체한다.

## 15. 일상 선택의 정보 위계 (2026-10-20)

- 현재 상황(별도 강조 패널) → '어떻게 할까?' → 행동 선택지 순서. 스탯 변화는 보조 정보로 줄이고, 선택 결과 설명은 정산 후 확인 화면에서만 보여준다.
- 선택·결과 확인 상태에서는 가짜 카운트다운을 숨긴다. 실제 미래 선택 시점이 존재하고 대기 상태가 아닐 때만 진행 게이지를 표시한다. 기존 모바일 시트 3단계와 rem/em 단위 유지.

## 15. 모바일 인생기록 시트 입력 처리 (2026-10-20)

- `html/game.html`의 기존 `#lifeSheet > #sheetToggle`, `.sheet-head`, `.sheet-content`를 유지한다. 바텀시트는 게임의 상시 UI이며 팝업/오버레이 생성·제거, 검은 배경 덮기, 본문 교체를 하지 않는다.
- 높이·경계·이징·축소 시 본문 숨김은 `css/style.css` 전담. 기본/축소는 `--sheet-small-height`(20dvh 내외), 중간은 55dvh, 전체는 `--sheet-large-height`(90dvh 내외). 선택 대기 여부가 시트 높이를 덮어쓰지 않는다.
- `js/game.js`는 단일 Pointer Events 경로로 손잡이와 헤더만 드래그한다. 버튼·링크에서 시작한 포인터는 무시한다. 이동 중에만 임시 CSS 변수 `--sheet-drag-height`를 전달하고 종료 시 삭제한다. style.height 직접 수정이나 Touch/Pointer 이벤트 중복 등록 금지.
- 손잡이 클릭·키보드는 축소→중간→전체→축소 순환. 드래그는 위치를 따라가되 방향과 임계거리로 인접 단계에만 정착한다. 드래그 후 합성 클릭을 억제하고, 기록/선택 단일 스크롤 및 PC 레이아웃은 보존한다.
- 높이 전환은 CSS, `prefers-reduced-motion` 존중. `tests/browser.mjs`에서 실제 터치·마우스 드래그·키보드 입력을 회귀 검증한다.
