# 생애 단계 · 출생 초기 데이터 — 1차 계약

> 2026-10-19. 실제 성장 스토리·전환 시점·경제 밸런스는 아직 구현하거나 확정하지 않았다. 기존 UI 생성값과 생애 ID를 정리한 첫 단계다.

## 단계 데이터

`js/playerState.js`의 `GukminPlayer.lifeStages`가 각 단계의 `id`, `label`, `next`, `metrics`를 제공한다. `phaseDefinition(id)`, `nextPhases(id)`로 조회할 수 있다.

| ID | 표시 | 대표 후속 경로 |
|---|---|---|
| `infant` | 출생·유년기 | `elementary` |
| `elementary` | 초등학생 | `middle` |
| `middle` | 중학생 | `high` |
| `high` | 고등학생 | `university` 또는 `adult` |
| `university` | 대학생 | `adult` |
| `adult` | 사회생활 | `political` |
| `political` | 정치활동 | `adult` |

`next`는 **대표적인 콘텐츠 이동 경로**일 뿐 강제 전환·자동 진행·조건 판정 로직이 아니다. 대학과 성인 여부, 직업과 정치 활동은 실제로 서로 겹칠 수 있다. 후속 콘텐츠 설계에서 이 모델을 분리하거나 넓히는 판단이 필요하다. 현재는 기존 `phase` ID를 유지하고, `GukminEffects.apply`의 `effects.attributes.phase`로 필요한 순간 명시적 변경을 허용한다. 나이 자체와 턴·실제 시계 간 대응은 정하지 않았다. 구 세이브에서 `phase`가 없는 경우의 `phaseOf` 나이 기준 추론은 레거시 호환용으로 보존한다.

## 출생 데이터와 값

`GukminPlayer.generate()`는 출생 정보를 다음과 같이 만든다.

- 이름: 기존 `NAMES` 샘플 중 하나를 뽑는다.
- 가정: 기존 `HOMES` 샘플 중 하나를 뽑고 `family`, `birthplace`, `description`을 서로 맞는 값으로 저장한다. 이 샘플의 동일확률 추첨은 임시 UI 생성 방식이며 실제 한국 인구·계층 분포를 주장하지 않는다.
- 생애: `age:0`, `phase:'infant'`, `job:'아기'`. 기존 학교/경력/역할 이력은 비어 있는 상태로 시작한다.
- 기본 특성: `traits:[]`. 출생 집안은 **속성**이므로 특성으로 중복 지급하지 않는다.
- 기본 상태값(`birthDefaults.stats`): `stress:0`, `health:100`, `money:0`. 나머지 용돈·관계·성적·내신·수능·수입·지지도·인지도는 `null`로 보존한다. 전 생애 노출 스탯만 초기 화면에서 표시한다.

숫자 0/100은 **현행 화면 호환용 시드값**이다. 의료적 해석, 집안 재력별 초기 재산, 특성 발생 확률, 성인 전환 시 수치 이관이나 시작 범위는 아직 확정하지 않았다. 지지도·인지도는 `university`/성인 단계 표시 데이터만 있으며 정치 입문 조건을 구현한 것이 아니다.

## 인트로 흐름

대기에서 인물은 이미 `ensure()`로 생성·보존된다. 시작 클릭 시 `html/waiting.html`의 정적 오버레이가 **해당 인물**의 이름·출생 배경을 약 3초 동안 연출한 뒤 `html/game.html`로 이동한다. 건너뛰기 버튼, Escape, `prefers-reduced-motion` 설정에서는 즉시 이동한다. 저장/재추첨/턴 진행은 하지 않으며 인게임도 새 스토리나 타이머를 자동 시작하지 않는다.

## 다음 콘텐츠 작업에서 결정할 것

유년기 에피소드·학교 입학 및 졸업 조건, 대학생과 성인의 중복 표현, 용돈/수입 전환, 관계의 특성 환산, 정치 진입 및 직업별 활성 지표, 출생 배경 분포와 밸런스, 연령/시간 드라이버. 확정 전까지 별도 엔진이나 자동 진행을 추가하지 않는다. 공통 정산·선택 구현은 [SYSTEMS.md](SYSTEMS.md)와 [PLAYER_STATE.md](../notes/PLAYER_STATE.md)를 참조한다.

## 최소 생애 자동 흐름 (2026-10-19)

- `js/data/base.js`는 기존 인물 생성에 쓰던 이름/가정/학교/스탯·특성/생애 단계와 출생 기본값을 **정적 자료**로 분리했다. 기존 샘플 분포 및 저장 키는 그대로 유지한다.
- `js/life/director.js`의 `GukminDirector.register({id,when,generate})`로 생애/역할별 오퍼레이터를 등록한다. `generate(persona)`는 기존 `GukminTimeline.create()` 계약의 이벤트·선택·정의 데이터를 반환한다. `when`은 각 이벤트 발생 조건과 함께 평가된다. 동일 세션 안에서 현재 생애 단계에 해당하는 오퍼레이터의 이벤트만 실행된다.
- `GukminDirector.create({persona,persist,onChange})`는 **단일 `contentId:'life-main-v1'`**인 타임라인과 동일한 `snapshot/advance/resolve/apply` API 및 `run/active`를 제공한다. 등록된 오퍼레이터의 정의는 세션 생성 시 하나의 카탈로그로 조립한다. 스토리 함수가 재실행되거나 이벤트 엔진을 단계마다 파괴하는 방식이 아니다. 단계 변경 후 `run`에서 활성 조건을 재평가한다.
- `run()`은 현재 턴에 등록된 사건을 처리하고, 조건이 이미 충족되는 확정적인 1회성 미래 사건의 예정 턴까지만 진행한다. 미응답 선택이나 남은 사건이 없으면 멈춘다. 반복 사건을 대상으로 무한히 시간을 진행하지 않으며, 나이 자동 증가나 실시간 타이머를 가정하지 않는다.
- 현재 작성된 `infant.js`는 0턴에 **출생 기록 정산 완료 여부만 표시**하는 첫 오퍼레이터다. 인물 생성 시 이미 저장된 두 출생 기록을 중복 생성하지 않는다. 그 외 스토리는 없으므로 바로 `이야기 준비 중` 상태로 남는다. 이후 실제 유년기 콘텐츠가 준비되면 생성 함수에 사건만 추가한다.
- 기존 시연·검증 콘텐츠(`systemDemo.js`, 외부 `GukminContent`)는 별도의 고정 콘텐츠로 유지한다. 개발 검증 버튼으로 명시적 전환할 때만 기존 세션을 교체한다.

## 출생 지역·가구 재력 생성 (2026-10-19)

- `js/data/regions.js`는 [지역 후보 255개](../notes/REGION_CATALOG.md)를 경로 ID 및 배열 태그로 이관한 정적 사전. `GukminRegions.all/find/tagged`로 모든 파일이 조회할 수 있다. 지역 추첨은 현재 균등 시연 추첨이며 현실의 출생 통계가 아니다.
- `GukminData.wealthTiers`에는 흙·동·은·금·다이아의 이름, 임시 출생 가중치(34/31/22/10/3), 나중에 사용하는 용돈값과 관계값을 정의한다. 부모 직업 유형(`homes`)·지역은 **서로 독립적으로 뽑으며** 특정 지역이 곧 부유/빈곤을 의미하지 않는다.
- `regionPresets`는 지역 태그 중 신도시/농촌/섬/상업/학군지의 작은 관계값 조정만 정의한다. 수치는 게임 시작값 예시이며 해당 주민의 실제 능력/성향/소득을 표현하지 않는다. 기본 건강/정신병/개인 재산은 기존 수치 유지. 용돈·관계는 출생 시 준비되지만 화면 노출은 기존 단계별 스탯 목록을 따른다.
- `playerState.generate()`는 출생지 ID·이름·태그, 재력 tier, 수저 특성을 같은 인물 데이터로 저장한다. `GukminStatus.traitToken()`은 인게임 토큰과 출생 인트로가 공유한다. 기존 생성 인물/세이브는 수정하지 않고 새 출생부터 적용한다.
