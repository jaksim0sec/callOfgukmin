# 생애 단계 · 출생 초기 데이터 — 1차 계약

> 2026-10-19. 1차 출생 기반 이후 **유년기→고교 졸업(19세)의 플레이 가능한 이야기 시연**을 추가했다. 게임용 확률·점수·진학 제한은 실제 통계나 공식 입학전형이 아니다.

## 단계 데이터

`js/playerState.js`의 `GukminPlayer.lifeStages`가 각 단계의 `id`, `label`, `next`, `metrics`를 제공한다. `phaseDefinition(id)`, `nextPhases(id)`로 조회할 수 있다.

| ID | 표시 | 대표 후속 경로 |
|---|---|---|
| `infant` | 출생·유년기 | `elementary` |
| `elementary` | 초등학생 | `middle` |
| `middle` | 중학생 | `high` |
| `high` | 고등학생 | `university` 또는 `adult` |
| `university` | 대학생 | `adult` |
| `adult` | 사회생활 | `political` |
| `political` | 정치활동 | `adult` |

`next`는 **대표적인 콘텐츠 이동 경로**일 뿐 강제 전환·자동 진행·조건 판정 로직이 아니다. 대학과 성인 여부, 직업과 정치 활동은 실제로 서로 겹칠 수 있다. 후속 콘텐츠 설계에서 이 모델을 분리하거나 넓히는 판단이 필요하다. 현재는 기존 `phase` ID를 유지하고, `GukminEffects.apply`의 `effects.attributes.phase`로 필요한 순간 명시적 변경을 허용한다. 나이 자체와 턴·실제 시계 간 대응은 정하지 않았다. 구 세이브에서 `phase`가 없는 경우의 `phaseOf` 나이 기준 추론은 레거시 호환용으로 보존한다.

## 출생 데이터와 값

`GukminPlayer.generate()`는 출생 정보를 다음과 같이 만든다.

- 이름: 기존 `NAMES` 샘플 중 하나를 뽑는다.
- 가정: 기존 `HOMES` 샘플 중 하나를 뽑고 `family`, `birthplace`, `description`을 서로 맞는 값으로 저장한다. 이 샘플의 동일확률 추첨은 임시 UI 생성 방식이며 실제 한국 인구·계층 분포를 주장하지 않는다.
- 생애: `age:0`, `phase:'infant'`, `job:'아기'`. 기존 학교/경력/역할 이력은 비어 있는 상태로 시작한다.
- 기본 특성: `traits:[]`. 출생 집안은 **속성**이므로 특성으로 중복 지급하지 않는다.
- 기본 상태값(`birthDefaults.stats`): `stress:0`, `health:100`, `money:0`. 나머지 용돈·관계·성적·내신·수능·수입·지지도·인지도는 `null`로 보존한다. 전 생애 노출 스탯만 초기 화면에서 표시한다.

숫자 0/100은 **현행 화면 호환용 시드값**이다. 의료적 해석, 집안 재력별 초기 재산, 특성 발생 확률, 성인 전환 시 수치 이관이나 시작 범위는 아직 확정하지 않았다. 지지도·인지도는 `university`/성인 단계 표시 데이터만 있으며 정치 입문 조건을 구현한 것이 아니다.

## 인트로 흐름

대기에서 인물은 이미 `ensure()`로 생성·보존된다. 시작 클릭 시 `html/waiting.html`의 정적 오버레이가 **해당 인물**의 이름·출생 배경을 약 3초 동안 연출한 뒤 `html/game.html`로 이동한다. 건너뛰기 버튼, Escape, `prefers-reduced-motion` 설정에서는 즉시 이동한다. 저장/재추첨/턴 진행은 하지 않으며 인게임도 새 스토리나 타이머를 자동 시작하지 않는다.

## 다음 콘텐츠 작업에서 결정할 것

유년기 에피소드·학교 입학 및 졸업 조건, 대학생과 성인의 중복 표현, 용돈/수입 전환, 관계의 특성 환산, 정치 진입 및 직업별 활성 지표, 출생 배경 분포와 밸런스, 연령/시간 드라이버. 확정 전까지 별도 엔진이나 자동 진행을 추가하지 않는다. 공통 정산·선택 구현은 [SYSTEMS.md](SYSTEMS.md)와 [PLAYER_STATE.md](../notes/PLAYER_STATE.md)를 참조한다.

## 최소 생애 자동 흐름 (2026-10-19)

- `js/data/base.js`는 기존 인물 생성에 쓰던 이름/가정/학교/스탯·특성/생애 단계와 출생 기본값을 **정적 자료**로 분리했다. 기존 샘플 분포 및 저장 키는 그대로 유지한다.
- `js/life/director.js`의 `GukminDirector.register({id,when,generate})`로 생애/역할별 오퍼레이터를 등록한다. `generate(persona)`는 기존 `GukminTimeline.create()` 계약의 이벤트·선택·정의 데이터를 반환한다. `when`은 각 이벤트 발생 조건과 함께 평가된다. 동일 세션 안에서 현재 생애 단계에 해당하는 오퍼레이터의 이벤트만 실행된다.
- `GukminDirector.create({persona,persist,onChange})`는 **단일 `contentId:'life-main-v1'`**인 타임라인과 동일한 `snapshot/advance/resolve/apply` API 및 `run/active`를 제공한다. 등록된 오퍼레이터의 정의는 세션 생성 시 하나의 카탈로그로 조립한다. 스토리 함수가 재실행되거나 이벤트 엔진을 단계마다 파괴하는 방식이 아니다. 단계 변경 후 `run`에서 활성 조건을 재평가한다.
- `run()`은 현재 턴에 등록된 사건을 처리하고, 조건이 이미 충족되는 확정적인 1회성 미래 사건의 예정 턴까지만 진행한다. 미응답 선택이나 남은 사건이 없으면 멈춘다. 반복 사건을 대상으로 무한히 시간을 진행하지 않으며, 나이 자동 증가나 실시간 타이머를 가정하지 않는다.
- 현재 작성된 `infant.js`는 0턴에 **출생 기록 정산 완료 여부만 표시**하는 첫 오퍼레이터다. 인물 생성 시 이미 저장된 두 출생 기록을 중복 생성하지 않는다. 그 외 스토리는 없으므로 바로 `이야기 준비 중` 상태로 남는다. 이후 실제 유년기 콘텐츠가 준비되면 생성 함수에 사건만 추가한다.
- 기존 시연·검증 콘텐츠(`systemDemo.js`, 외부 `GukminContent`)는 별도의 고정 콘텐츠로 유지한다. 개발 검증 버튼으로 명시적 전환할 때만 기존 세션을 교체한다.

## 출생 지역·가구 재력 생성 (2026-10-19)

- `js/data/regions.js`는 [지역 후보 255개](../notes/REGION_CATALOG.md)를 경로 ID 및 배열 태그로 이관한 정적 사전. `GukminRegions.all/find/tagged`로 모든 파일이 조회할 수 있다. 지역 추첨은 현재 균등 시연 추첨이며 현실의 출생 통계가 아니다.
- `GukminData.wealthTiers`에는 흙·동·은·금·다이아의 이름, 임시 출생 가중치(34/31/22/10/3), 나중에 사용하는 용돈값과 관계값을 정의한다. 부모 직업 유형(`homes`)·지역은 **서로 독립적으로 뽑으며** 특정 지역이 곧 부유/빈곤을 의미하지 않는다.
- `regionPresets`는 지역 태그 중 신도시/농촌/섬/상업/학군지의 작은 관계값 조정만 정의한다. 수치는 게임 시작값 예시이며 해당 주민의 실제 능력/성향/소득을 표현하지 않는다. 기본 건강/정신병/개인 재산은 기존 수치 유지. 용돈·관계는 출생 시 준비되지만 화면 노출은 기존 단계별 스탯 목록을 따른다.
- `playerState.generate()`는 출생지 ID·이름·태그, 재력 tier, 수저 특성을 같은 인물 데이터로 저장한다. `GukminStatus.traitToken()`은 인게임 토큰과 출생 인트로가 공유한다. 기존 생성 인물/세이브는 수정하지 않고 새 출생부터 적용한다.

## 유년기~고교 졸업 스토리 플레이 (2026-10-19 확장)

### 오퍼레이터와 콘텐츠

- `js/life/story.js`: 공통 `notice/selection/exam/pack` 생성기. 이벤트 종류·선택 종류·정산 구조는 기존 시스템 계약을 유지한다.
- `js/life/infant.js`: 0~6세 출생, 가정별 일상, 지역적 배경, 초등 입학.
- `js/life/elementary.js`: 7~12세 친구, 돌봄·방과 후, 진로 체험, 졸업/중학 입학.
- `js/life/middle.js`: 13~15세 6회 중간·기말 시험, 선택형 교육 자원, 거주지별 고교 진학 지원서.
- `js/life/high.js`: 16~18세 3학년×(3모·중간·6모·기말) 총 12회 시험, 19세 고교 졸업 후 다음 이야기 대기.

나이와 시계는 절대 시간이 아니라 **사건 순서용 정수 턴**에 고정한 서사 마일스톤으로 변화한다. 0턴 출생, 28턴 초등 입학, 52턴 중학 입학, 63턴 고교 선택, 79턴 19세 졸업. 개발용 시간 버튼이 아니라, 미해결 선택이 없다면 관제탑이 다음 기획 사건까지 턴을 진행한다. 실제 벽시계 타이머는 없다.

시험의 다섯 선택지는 준비 강도에 따라 `study`·`schoolScore`(내신) 또는 `exam`(모의고사), `stress`·`health`가 변화한다. 결과는 기존 `Effects.apply`를 통해 정산·저장된다. 숫자 0~100 범위는 게임 수치이고 진짜 성적 등급은 아니다.

### 지역별 실제 학교 이름·입시 정보의 한계

- `js/data/schools.js`: 17개 지역 그룹당 실재 학교명 후보 3곳(총 51개 이름)을 포함한다. 성남·수원·고양 출생은 일반학교 첫 후보를 추가 보정한다. 상세 주소와 원거리 통학, 배정 학군, 성별 제한 등은 **미모델링**이다.
- 고교 지원서 `presentation.type:'school'`: 이름, 유형, 가상 학교 문장 마크/확인된 일부 교표, 게임 내 학업·내신 조건, 수치 변화 등을 표시한다.
- 특목고/영재학교 **합격 기준은 공식 전형을 나타내지 않으며**, 학교별 내신·출결·면접·전형절차를 일괄 숫자 하나로 치환한 사실로 받아들여서는 안 된다. 실제 전형은 당해연도 교육청·학교 요강을 확인해야 한다.
- 실제 학교 교표는 출처와 사용 가능성이 확인된 일부만 이미지로 연결했다. 아직 검증하지 못한 학교에는 임의 제작한 '공식 교표' 대신 문자형 *임시* 마크를 표시한다. 51개 학교 중 일부 후보는 이름 존재 외 공식 학교정보·교육과정 대조가 미완료다.
- 실제 소득 수준/지역/성별과 학업 능력의 인과관계를 고정하지 않는다. 가정별로 가용 수업 자원과 서사만 달라지고, 무료 학습 경로를 별도로 마련했다.
- 출생 데이터와 이전 저장 키는 보존한다. 고교 선택의 정확한 학교명은 선택 결과의 `schoolHistory`에 기록하고, 졸업 사건은 현재 재학 중인 한 개 고등학교를 찾아 졸업 처리한다.

### UI

`js/majorView.js`는 `GukminGame.registerMajorPresenter`만 사용하고 기존 `timeline`의 5지선다 선택지 상태를 그대로 처리한다. `html/game.html`의 별도 네이티브 `dialog`에서 시험지/학교 지원서를 렌더하며 PC·모바일 공용이다. ESC로 창을 닫아도 선택이 취소되지 않으며 '다시 열기' 버튼이 남는다. 응답 후 동일 결제·정산이 다시 적용되지 않는다. 기본 콘텐츠가 끝나면 진행도는 **이야기 준비 중**으로 돌아간다.

## 고교 후보 자료 정합성 보완 (2026-10-19)

- 기본 17권역 51개 학교 후보는 시연 표본이다. 기존 경기도 출생지 목록은 성남·수원·**평택**으로 구성되어 있으므로 시별 고교 후보를 따로 지정했다. 성남은 분당중앙고·분당고·성남외고, 수원은 영덕고·매탄고·수원외고, 평택은 현화고·비전고·경기물류고다. 추가 고양시 후보는 차후 지역 확장을 대비한 조회용이다.
- 기존의 ‘두 번째 학교는 모두 일반고’ 분류 오류를 수정했다. `autonomous`(휘문·해운대·북일), `autonomous-public`(현화), `foreign`, `international`(고양국제), `gifted`(광주과학·세종과학예술영재), `vocational`(경기물류)과 `general`을 구분한다.
- 사용자가 학교를 선택하기 전 게임에 표시되는 학업·내신 수치 제한은 **게임 규칙**이며 해당 학교의 공식 고입 모집 기준이 아니다. 실제 일반고 배정 방식/특성화고 전형은 별도이다. 모든 학교 후보의 실제 입학 자격(거주지·성별·학군·모집 연도)은 미모델링 상태다. 특정 학교의 수업 수준·입시 경쟁률을 게임 스탯과 동일시하지 않는다.
- 가정 형편에 따라 달라지는 진학 준비 일상 선택을 중3 시기에 추가했다. 소득·지역이 개인의 능력이나 시험 점수를 자동 결정하지 않으며, 무료 교육청 설명회·교사 상담 경로를 보존한다.
- 출처 불명의 외부 교표 이미지 2건은 제거했다. 공식 교표를 안전하게 확인·사용 가능해지기 전에는 문자형 임시 식별 마크(툴팁 표기)만 표시한다. 자료 링크는 확인한 학교·전형 자료를 가리키고 그렇지 않은 학교는 고입정보포털로 연결한다.


## 고교 연간 학업 선택과 학교별 일상 콘텐츠 (2026-10-19 최신)

- 기존 고교 1학년당 4회(3월 모의고사·중간고사·6월 모의고사·기말고사) 팝업은 중단. 이제 각 학년마다 **모의고사 전체 노력 1회, 내신 전체 노력 1회**, 3년 합계 6회의 한방 선택이다. 중학교 6회 시험 선택은 유지한다.
- 시험 사이에 학급 단체방, 통학편, 수행평가, 학점제 선택과목, 친구의 고민, 가족과의 약속, 졸업사진 관련 일상 사건을 배치했다. 가정 형편과 거주 지역에 따라 이야기 문구·선택지가 달라진다.
- 고교 진학을 결정하면 schoolTrack과 schoolProgram 숨김 속성이 저장된다. 선택한 고교 유형에 따라 교내 활동 사건이 달라지며, 공개 교육과정을 확인한 분당중앙고 과학·수학 활동 및 휘문고 과목선택 자료는 개별 학교 사건에 사용한다. 학교의 공식 평가나 학생 수준 서열로 해석해서는 안 된다.
- 이전 콘텐츠 ID life-main-v1을 유지하고 이전 고교 시험 12개 ID는 신규 발생하지 않게 비활성화된 데이터 정의로 남겼다. 기존 진행 중인 시험 선택 토큰의 복구를 위한 것이다.
- data/grades.js는 중학교 A~E 성취도, 고교 내신 5등급, 모의고사 9등급을 게임 0~100 지수로 **예상** 표시한다. 학생별 석차와 과목별 성적 데이터가 없으므로 실제 성적·등급이 아니다. 5등급 누적 10/34/66/90/100%, 9등급 누적 4/11/23/40/60/77/89/96/100% 경계를 사용한다.


## 2026-10-19 유년기 특성·성장 중 용돈

- 출생 후 첫 유년기 주요 일상 3개(인형·모래삽·입학 전 준비)를 **유아의 직관적인 행동**으로 바꿨다. 선택지 ID와 선택 수는 유지하면서 `호기심`, `낯가림`, `고집`, `배려심`, `느긋함` 등의 특성을 획득하게 만들었다. 기존 수저 특성은 유지한다.
- 생애 관제탑은 초등학교 입학(만 7세) 이후 학교 재학 기간 동안 정수 턴마다 재력 티어의 용돈 지급액을 보유 스탯 `allowance`에 누적한다. 유아는 지급 대상에서 제외한다. 이는 실제 월별 지급 통계가 아닌 게임 턴 단위 간단한 시스템이며 계층별 금액은 `data/base.js`의 기존 시연 수치. 턴마다 한 번만 기록되며 새로고침 중복 적용 없음.
- 출생 인트로는 10초 자동 시작 및 수동 `출생하기` 버튼. 유년기~고교 타임라인의 스토리 사건 전환 턴 자체는 변경하지 않는다.
- `timeline.js` 선택 정산에는 생애 세션 한정 `pauseAfterChoice`를 적용. 정산 후 `runtime.awaitingContinuation=true`를 저장한다. 사용자가 `run()`으로 다음 이야기를 요청해야 재개하며, 이전 공통 엔진 콘텐츠는 이 기능이 기본 비활성이라 기존 동작을 유지한다.

## 용돈 정산 (2026-10-20)

- 학생 시기(7~18세)의 `allowance`는 턴당 용돈 지급액으로 유지하며 각 턴마다 해당 금액을 `money`에 적립한다. 용돈 금액 자체는 자동 증가하지 않는다. 기존 턴·저장 키 보존.
