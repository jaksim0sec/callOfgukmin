# 국민의 부름 — UI 기반 시연

현재 코드는 **인물·화면 UI와 데이터 기반 공통 게임 시스템**이다. 명시적인 검증 모드에서 공통 정산·진행을 실행할 수 있다. 실제 생애 콘텐츠·선거·엔딩은 아직 만들지 않았다. 기존 인생 진행 세이브를 삭제하거나 재활성화하지 않는다.

## 화면

- **대기** (`html/waiting.html`): 이름·출생 배경·포스터, 새 인물 생성, 인게임 진입, 결과 화면 미리보기.
- **인게임** (`html/game.html`): PC 2열 / 모바일 포스터·속성 정보 + 항상 열린 인생 기록 바텀시트. 속성 스탯은 왼쪽, 상태 스탯·특성 토큰은 오른쪽.
- **결과** (`html/result.html`): 별도 결과 레이아웃. 현재는 종료 판정이 없는 **미리보기**만 가능.
- `index.html`은 대기 화면으로 이동하는 진입점이다. `html/`의 세 파일은 **독립 HTML 페이지**이며 `js/boot.js`가 클릭 시 브라우저 페이지를 이동시킨다. 동적 `fetch` 없이 작동한다.

## UI 기반 기능

- 이름·지역·가정 배경 무작위 생성, 현행 UI용 키 `callOfgukmin__ui__v1`에 로컬 저장/복원, 새 인물 생성.
- 기존 공통 `GukminPoster.create/update`로 각 화면에서 인물 포스터 표시.
- 속성 스탯의 출생지·집안·현재 역할 표시, 학력은 **교표형 SVG 아이콘+학교명 알약 토큰**으로 누적 가능. 재학 중만 강조 테두리/배경을 적용하고 졸업은 일반 토큰으로 보존.
- 상태 스탯은 생애 단계에 따라 동적으로 활성 목록 표시(0세는 기본 3개). 아래에 특성을 **SVG 라인 아이콘+이름 토큰**으로 표시. 특성은 데이터로 정의한 상황 수정·반복 효과와 연결된다.
- 개발 검증 모드의 진학 서류·가상 정당 투표지 선택 UI 미리보기. 선택해도 인물 데이터·시간·정치 상태를 변경하지 않는다.

## 개발

```sh
node tests/smoke.mjs
node --test tests/systems.mjs
python3 -m http.server 8000
```

대기·인게임·결과 화면은 각각 HTML을 직접 열 수 있다. 정적 `<base href="../">`로 Pages의 `/callOfgukmin/` 및 로컬 경로에서 CSS·JS를 로드한다. HTTP 정적 서버 또는 GitHub Pages에서 실행한다.

- [AGENTS.md](./AGENTS.md): 개발 규칙
- [docs 안내](./docs/README.md): 문서 분류
- [실제 실행 구조](./docs/developing/RUNTIME.md): 화면/데이터 책임
- [CSS 변경 규칙](./docs/developing/CSS.md): CSS 수정 전 필독
- [인물 상태 설계](./docs/notes/PLAYER_STATE.md): 속성·상태·특성
- [출생 지역 사전](./docs/notes/REGION_CATALOG.md): 기획 데이터, 미연결

**검증:** 정적 스모크로 파일 참조/구문/DOM 계약을 검사한다. 화면의 실제 사용감과 브라우저 간 렌더링은 별도 실기기 확인이 필요하다. 과거 `callOfgukmin__playable__v1` 세이브는 건드리지 않는다.


공통 시스템의 데이터 형식·API·진행 및 검증 시나리오는 [SYSTEMS.md](docs/developing/SYSTEMS.md)를 참조한다. 인게임의 `?systems=1`에서 공통 시스템 검증을 시작할 수 있다. 기본 화면은 기존 상태/미리보기 안내를 제거하고 실제 일상 선택이 발생할 때 선택지를 표시한다. 한방 선택은 대기 기반만 있으며 단계별 팝업은 후속 개발한다.

실제 Chromium A–F 검증은 `node tests/browser.mjs`로 실행한다(개발 도구 Playwright/Chromium 필요, 배포 의존성 없음). PC·모바일 3개 해상도, 저장 복구·예전 세이브 보존·미리보기 비변경·한방 콜백을 검사한다. 실제 생애 콘텐츠·엔딩·시간 배율·게임 밸런스는 미구현/미확정이다.
